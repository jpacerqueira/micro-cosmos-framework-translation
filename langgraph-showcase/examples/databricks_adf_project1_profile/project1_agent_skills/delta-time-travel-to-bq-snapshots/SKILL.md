# Delta Time Travel → BigQuery Snapshots

## Source patterns in this project

### Python API (ETLPipeline._read_delta_as_of)

```python
def _read_delta_as_of(self, path, *, version=None, timestamp=None):
    reader = self.spark.read.format("delta")
    if version is not None:
        reader = reader.option("versionAsOf", int(version))
    if timestamp is not None:
        reader = reader.option("timestampAsOf", timestamp)
    return reader.load(path)
```

Used in `serve_data()`:
```python
df = self._read_delta_as_of(silver_path)  # latest
df = self._read_delta_as_of(silver_path, version=3)  # v3
df = self._read_delta_as_of(silver_path, timestamp="2024-01-15 00:00:00")
```

### SQL cells (notebooks)

```sql
SELECT * FROM delta.`/mnt/serving/trusted/fact_sales_orders` VERSION AS OF 5
SELECT * FROM delta.`/mnt/serving/trusted/fact_sales_orders` TIMESTAMP AS OF '2024-10-01'
```

## BigQuery equivalents

BigQuery has no native Delta time travel. The migration pattern depends on use case:

### Use case 1: Point-in-time analytical queries (daily snapshots)

db2bq emits `workflows/snapshots_daily.yaml` — a daily Cloud Workflow that creates
a BigQuery snapshot of each gold table:

```yaml
# Auto-generated by db2bq
main:
  steps:
    - SnapshotFactSalesOrders:
        call: http.post
        args:
          url: https://bigquery.googleapis.com/bigquery/v2/projects/my-project/jobs
          body:
            configuration:
              copy:
                sourceTables:
                  - projectId: my-project
                    datasetId: gold
                    tableId: fact_sales_orders
                destinationTable:
                  projectId: my-project
                  datasetId: gold_snapshots
                  tableId: fact_sales_orders_${{ sys.now() | date("%Y%m%d") }}
                createDisposition: CREATE_IF_NEEDED
                operationType: SNAPSHOT
```

Query a snapshot:
```sql
SELECT * FROM `my-project.gold_snapshots.fact_sales_orders_20241001`
```

### Use case 2: Row-level time travel (SCD2 / audit)

If the source uses Delta time travel for SCD2 or audit purposes, model it as a
**change data capture** table with `_valid_from` / `_valid_to` columns:

```sql
-- BigQuery SCD2 query
SELECT * FROM `my-project.gold.dim_item`
WHERE _valid_from <= TIMESTAMP('2024-10-01')
  AND (_valid_to IS NULL OR _valid_to > TIMESTAMP('2024-10-01'))
```

### Use case 3: VERSION AS OF (Delta version number)

BigQuery has no version numbers. Use the named snapshot approach:
- Store a mapping of `version → snapshot_table_suffix` in a BigQuery metadata table
- Query: `SELECT * FROM gold_snapshots.fact_sales_orders_v5` (manually created)

## Gold window SQL → Dataform SQLX

The `sql/gold_windows/` Spark SQL files using time travel need rewriting:

**Source (Spark SQL):**
```sql
SELECT * FROM delta.`/mnt/serving/customer_transactions` VERSION AS OF 0
```

**Target (BigQuery via Dataform):**
```sql
-- In definitions/gold/customer_transactions_initial_snapshot.sqlx
config { type: "view", tags: ["snapshot"] }
SELECT * FROM `my-project.gold_snapshots.customer_transactions_20240101`
```

## create_gold_view() → Dataform view

The `create_gold_view()` method creates a Spark temp view for ad-hoc SQL access.
db2bq translates this to a Dataform view SQLX:

**Source:**
```python
def create_gold_view(self, table_name, view_name=None, version=None, timestamp=None):
    gold_path = f"{self.serving_path}/{table_name}"
    df = self._read_delta_as_of(gold_path, version=version, timestamp=timestamp)
    resolved = view_name or f"{table_name}_gold"
    df.createOrReplaceTempView(resolved)
    return resolved
```

**Output (`definitions/gold/v_fact_sales_orders.sqlx`):**
```sql
config {
  type: "view",
  tags: ["medallion:gold", "view"]
}
-- Auto-generated Dataform view for the gold serving layer.
SELECT *
FROM ${ref('fact_sales_orders')}
```

For time-travel views, customise the SQLX to reference the appropriate snapshot table.
